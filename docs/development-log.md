# 개인 개발 및 버전 관리 기록

## 작업 기준

담당자 안내에 따라 팀 협업 대신 개인 프로젝트로 진행합니다. `feat/moa-sns`에서 구현을 나누어 기록하고 최종본을 `main`에 통합합니다. 다른 사람의 이름으로 커밋하거나 허위 협업 기록을 만들지 않습니다.

## 구현 구분

1. 기본 구조와 Spring Boot API: 인증, 게시물, 반응, 관계, 신고·운영
2. React UI: 반응형 피드, 게시물 상세·작성·수정, 프로필·내 활동
3. 검증: 실제 HTTP 통합 테스트, 파일·숨김 접근 통제, CI
4. 제출 문서: MVC 비교 예제, 실행 방법, 화면·코드 캡처

GitHub의 Commits·Branches 화면에서 실제 커밋 메시지와 브랜치를 확인할 수 있습니다. 한 사람이 수행한 변경이므로 팀원 간 리뷰나 공동 작업으로 기술하지 않습니다.

## 로컬 확인

- 백엔드 테스트: Java 25에서 Java 21 대상으로 컴파일, H2 메모리 DB에서 HTTP 통합 테스트 14개 통과
- 백엔드 패키지: Spring Boot 실행 JAR 생성
- 프론트: Vite 프로덕션 번들 생성, 로컬 환경의 자식 프로세스 실행 제약 때문에 인프로세스 Babel 변환을 적용한 검증 경로 사용
- 표준 `npm ci`, `npm run build`, 프론트 API 테스트 4개가 GitHub Actions의 Linux 환경에서 통과
- Java 21의 GitHub Actions에서도 백엔드 테스트·패키지 검증 통과
- [실제 CI 실행 결과](https://github.com/WonJiSun0730/projectmoa/actions/runs/41565403689)
- 실제 브라우저: 로그인, 홍보 글 저장, 상세 페이지, 댓글 작성, 내 활동 집계 확인
- 모바일: 360px 대응, 가로 넘침 없음

## 향후 개선

- 기존 MVC 프로젝트가 제공되면 비교 예제를 실제 기존 코드와 diff로 대체
- 이메일 인증·비밀번호 재설정·로그인 시도 제한
- 게시물과 이미지 등록을 초안/발행 방식으로 통합
- 다수 게시물 조회의 부가정보 일괄 조회와 부하 시험
- React 컴포넌트를 파일별로 분리하고 화면 자동화 테스트 확장
- WebP 이미지 지원과 실제 MySQL 버전용 스키마 마이그레이션
- 필요 시 노출·링크 클릭 이벤트와 집계 범위 정의
